## そもそもIAMと、IAM Identity　centerって何が違うの

IAMの詳しい説明は省きますが、ざっくり言うと「AWSで、誰が何をしてよいかを管理する仕組み」です。元々AWSにログインするユーザーにIAMを配布している時期がありましたが、昨今はセキュリティの設定のためにサービスにIAMを設定したりして、そのサービスからのみアクセスを許容する。みたいな設定ができます

IAM Identity Center は、IAMより後から登場した、複数のAWSアカウントへのログインをまとめて管理するためのサービスです。もとは「AWS Single Sign-On（AWS SSO）」という名前で、2022年に今の名前へ変わりました。
IAMユーザーを置き換えるものではなく、裏側では、各アカウントにIAMロールが自動で作られ、ユーザーはそのロールを使ってログインします。
ざっくり言うと「IAMの上に乗った、人のログインを管理する仕組み」です。

| 項目 | IAM（IAMユーザー） | IAM Identity Center |
| --- | --- | --- |
| 管理する範囲 | 1つのAWSアカウントの中だけ | Organizations配下の複数アカウントをまとめて管理 |
| ユーザーの作成場所 | アカウントごとにIAMユーザーを作る | Identity Centerに一度作れば、複数アカウントで使える |
| ログイン方法 | アカウントごとに、IDとパスワードでログイン | AWSアクセスポータルから、1回のログインで各アカウントへ |
| 権限の定義 | IAMポリシーをユーザーやグループに付ける | 許可セット（Permission Set）をアカウントに割り当てる |
| 認証情報 | 長期のアクセスキー（漏えいリスクが高い） | 一時的な認証情報（自動で期限切れになる） |
| CLIの設定 | `aws configure` でアクセスキーを登録 | `aws configure sso` / `aws sso login` |
| 外部IdPとの連携（SSO） | 1アカウントずつ個別に設定（SAMLフェデレーション） | Entra ID、Okta、Google Workspaceなどと一元的に連携 |
| 退職者・異動者の対応 | アカウントごとにユーザーを削除する | 1か所で無効にすれば、全アカウントに反映 |
| 主な用途 | ロール、サービス間の権限、例外的な用途 | 人がAWSにログインするときの標準の方法 |
